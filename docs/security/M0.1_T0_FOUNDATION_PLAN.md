### 1.1 Why the app cannot be imported in a test today (import-time side effects)
Importing `main` (the only way to get `app`) triggers, in this order:
1. `orchestrator` → each of 7 `agents/*.py`: `load_dotenv()`, `AsyncGroq(api_key=os.environ["GROQ_API_KEY"])` (**KeyError if unset**), `ShortTermMemory()` / `LongTermMemory()`.
2. `memory/long_term.py`: `load_dotenv()`, `DATABASE_URL = os.getenv(...)`, `create_engine(DATABASE_URL, ...)` (**error if unset**), then **`Base.metadata.create_all(engine)` — opens a real PostgreSQL connection at import**. An import without a reachable Postgres fails.
3. `short_term.py`, `scheduler.py`, `self_improver.py`: `redis.Redis.from_url(...)` — lazy, no connection until first command (safe to import).
4. `improvement/analyzer.py`, `voice_handler.py`: more `AsyncGroq(...)`; `voice_handler` does `os.environ["GROQ_API_KEY"]`.
5. `telegram_bot.py`: imports python-telegram-bot, `load_dotenv()`, own `AgentOrchestrator()`/`LongTermMemory()`.
6. `main.py`: module-level `app`, CORS, and singletons.

`load_dotenv()` is called at import in 12 modules; `find_dotenv()` searches from each *calling file's* directory upward, so a developer's real `backend/.env` is silently loaded by any test that imports these modules, **filling any variable not already set** (it never overrides existing variables, even empty ones). A test that doesn't pre-set `TELEGRAM_BOT_TOKEN` could therefore start the real bot.

### 1.2 Minimum compatible test setup (recommendation)
| Candidate | Verdict |
|---|---|

| `pytest-asyncio` | **Do not add now.** `anyio` (installed) ships a pytest plugin (`@pytest.mark.anyio`) for any later async-service tests; sync `TestClient` covers T0. Revisit only if a concrete need appears. |

Isolation rules for the foundation: (a) `conftest.py` pre-sets every env var that legacy modules read (dummy values) so `.env` can never leak in and the Telegram bot never starts; (b) an autouse fixture blocks `socket.socket.connect` so any accidental Redis/Postgres/Groq/network access fails the test loudly; (c) DB for tests = SQLite **file** in `tmp_path` (not `:memory:` — SQLAlchemy uses a per-thread pool for in-memory SQLite, so tables created in a worker thread would be invisible elsewhere); (d) settings tests inject an explicit `environ` mapping and never touch `os.environ`.

## 3. CORS and API documentation: current behaviour and policy

### 3.1 Current (verified in `main.py`)
- `CORSMiddleware(allow_origins=["http://localhost:3000"], allow_credentials=True, allow_methods=["*"], allow_headers=["*"])`.
- `FastAPI(title="Multi-Agent Startup OS", lifespan=lifespan)` with no docs overrides ⇒ `/docs`, `/redoc`, `/openapi.json` (and `/docs/oauth2-redirect`) are served in every environment.
- WebSocket `/ws` is not subject to CORS and has no Origin check (T8).

### 3.2 Proposed policy
| Aspect | Proposal |
|---|---|
| Source of truth | `CORS_ALLOWED_ORIGINS` env var: comma-separated exact origins (`scheme://host[:port]`). Parsed/validated in `config.py`. |
| Defaults | `development`/`test`: `http://localhost:3000,http://127.0.0.1:3000`. `production`: **empty list** (no cross-origin access until explicitly configured). No domain is assumed — the Vercel domain must be supplied by the owner (see §9). |
| Validation | Reject `*`, `null`, entries without scheme/host, with paths/query/fragment, non-http(s); normalize (strip trailing `/`, lowercase scheme/host), dedupe. In production require `https` (except none for localhost, which is not allowed in prod). |
| Credentials | `allow_credentials=False`. The target contract uses `Authorization: Bearer`, not cookies, so credentialed CORS is unnecessary and `*`-style misconfig becomes harmless. |
| Methods / headers | `allow_methods=["GET","POST","DELETE","OPTIONS"]` (the only verbs used by the frontend), `allow_headers=["Authorization","Content-Type"]`, `max_age=600`. |
| WebSocket origins | Same list reused by T8 (`settings.allowed_origins`); no separate variable in T0. |
| Docs | `API_DOCS_ENABLED` (bool). Default: `true` in `development`/`test`, `false` in `production`. In `production`, setting it `true` is a **startup error** (docs can never be exposed by accident). When disabled the app is built with `docs_url=None, redoc_url=None, openapi_url=None` (also removes the oauth2 redirect), so all three return 404. |
| Where supplied | Backend: the server process environment / env file on the VM (**location unknown** — see U6 in the exposure report; local dev: `backend/.env`, which T0 does not edit). Frontend base URLs (T9) via Vercel project env (`NEXT_PUBLIC_*`). Neither is changed by this task. |

## 4. Proposed configuration architecture (typed settings, fail-fast)

New module `backend/config.py` (no new dependency; uses `pydantic`, already installed as a FastAPI dependency):
- `Settings`: frozen pydantic `BaseModel` with `model_config = ConfigDict(frozen=True, extra="forbid", hide_input_in_errors=True)`; secret fields typed `SecretStr` (masked in `repr`/`str`/dumps).
- `load_settings(environ: Mapping[str, str] | None = None) -> Settings`: builds from an explicit mapping (defaults to `os.environ`); treats empty/whitespace values as unset; collects **all** problems and raises one `ConfigError` whose message lists `VARIABLE: reason` only — **never values** (pydantic's `ValidationError` is caught and re-rendered from `loc` + our own messages).
- `get_settings()`: cached accessor that calls `load_dotenv(override=False)` once, then `load_settings()`; `reset_settings_cache()` for tests.
- `Settings.safe_summary() -> dict`: booleans/counts only (e.g. `{"env":"production","docs":false,"cors_origins":1,"groq_key_set":true}`) for the single startup log line.
- Rejected alternative: `pydantic-settings` (extra dependency; its default error output includes input values; we need custom redaction anyway).

### 4.1 Fields and validation
| Setting (env var) | Type / default | Required | Validation / behaviour |
|---|---|---|---|
| `app_env` (`APP_ENV`) | `development`\|`test`\|`production`; **unset ⇒ `production`** (fail-safe) | no | invalid value → error. Local dev sets `APP_ENV=development` (owner action in their `.env`, not done by T0). *Open decision T0-D1.* |
| `groq_api_key` (`GROQ_API_KEY`) | `SecretStr` | **yes (all envs)** | non-empty. Same fail-fast the code has today, but with a clear message |
| `model_name` (`MODEL_NAME`) | str, default `llama-3.3-70b-versatile` | no | non-empty |
| `database_url` (`DATABASE_URL`) | `SecretStr` | **yes** | scheme must be `postgresql…`; `sqlite…` allowed **only** when `app_env=test`; value never printed |
| `redis_url` (`REDIS_URL`) | str, default `redis://localhost:6379` | **no (cannot be mandatory yet)** | scheme ∈ {`redis`,`rediss`,`unix`}; in production an unset value logs a WARNING (current deployment may rely on the default) |
| `telegram_bot_token` (`TELEGRAM_BOT_TOKEN`) | `SecretStr \| None` | no | presence ⇒ bot starts (unchanged semantics) |
| `twilio_account_sid`, `twilio_auth_token` | `SecretStr`, default `""` | no (becomes required-when-voice-enabled in T11) | – |
| `allowed_origins` (`CORS_ALLOWED_ORIGINS`) | `tuple[str,...]` | no | §3.2 rules |
| `api_docs_enabled` (`API_DOCS_ENABLED`) | bool, env-dependent default | no | `true` in production → error |
| `auth_config_required` (`AUTH_CONFIG_REQUIRED`) | bool, default **false in T0** (flips to `true` in T5) | no | when true, the three auth settings below are mandatory in production |
| `auth_jwt_issuer` (`AUTH_JWT_ISSUER`) | default `agentforge-web` | no | non-empty |
| `auth_jwt_audience` (`AUTH_JWT_AUDIENCE`) | default `agentforge-api` | no | non-empty |
| `auth_jwt_public_keys` (`AUTH_JWT_PUBLIC_KEYS`) | JSON object `{kid: PEM}` | only when `auth_config_required` and production | **Structural** validation only in T0: valid JSON, ≥1 entry, unique non-empty `kid`s, each value is a PEM `PUBLIC KEY` block, **rejects any value containing `PRIVATE KEY`** (backend must never hold the private key). Cryptographic validation (EC P-256 parse) needs `cryptography` and is deferred to T5. |

Algorithm is **not** configurable (fixed to `ES256` in T5) to prevent downgrade by misconfiguration.

### 4.2 Not made mandatory yet (would break the current deployment, whose environment is unknown)
`REDIS_URL` (relies on default), `TELEGRAM_BOT_TOKEN`, `TWILIO_*`, all `AUTH_*` (no keys exist until T4/T5), `CORS_ALLOWED_ORIGINS` (empty in production is *allowed* but logged at WARNING because the dashboard's REST calls need an entry). Also `APP_ENV` itself cannot be required yet; its unset default is `production`.

## 7. Risks and compatibility

| Risk | Detail | Mitigation |
|---|---|---|
| Unset `APP_ENV` ⇒ production | Existing deployment (env unknown) would get docs off and **empty CORS list**. Docs-off is intended; empty CORS can only change behaviour for localhost-against-prod callers (dashboard→API REST is already blocked by the current localhost-only list, per the exposure report). Deployment must set `CORS_ALLOWED_ORIGINS` to the real dashboard origin when T0 ships | explicit owner action; startup WARNING if empty in production |
| Existing `DATABASE_URL` scheme | Must start with `postgresql` (README form `postgresql://…`). A `postgres://` URL already fails in SQLAlchemy 2 | validation message names the variable |
| Moving `create_all` to lifespan | Anything importing `long_term` without starting the app no longer auto-creates tables (none exist in the repo). `uvicorn main:app` still creates them at startup, before Telegram starts. Becomes redundant when Alembic lands (T1) | `init_db()` kept explicit and idempotent |
| `get_settings()` at `long_term` import | Any module importing `long_term` now triggers config validation (fail-fast earlier, with clearer errors). Agents still `KeyError` on missing `GROQ_API_KEY` as before, but settings will report it first when reached via `main` | order independent: `get_settings()` calls `load_dotenv` itself |
| `load_dotenv()` leakage in tests | See §1.1 | conftest pre-sets all names; guard test |
| Circular imports | `config.py` imports nothing from the app; `app_factory.py` imports only `config` and FastAPI | none expected |
| Async/sync | `init_db()` is sync SQLAlchemy → run via `asyncio.to_thread` in the async lifespan; SQLite tests need a file DB (thread-affinity) | noted in conftest |
| CORS change from `allow_credentials=True` | No cookie-based backend auth exists; the Bearer design doesn't need credentials. WebSocket unaffected | none |
| Methods/headers narrowed | Frontend uses only GET/POST/DELETE and `Content-Type`; `Authorization` pre-allowed for T9 | verified by frontend grep |
| Telegram | Lifespan condition switches to `settings.telegram_bot_token`, but `telegram_bot.py:480` still reads the env itself — both must agree (they read the same variable) | untouched file, same variable |
| Local venv drift | `python-multipart`, `cryptography`, `pytest` absent; `pyjwt` undeclared | T0 only needs `pytest`; others handled at T5/T11 |
